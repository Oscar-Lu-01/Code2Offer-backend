流量控制+熔断

流量控制：
1、防止过载： 保证系统不挂
2、防止雪崩效应：防止某个模块崩溃后依赖的模块全部能馈
3、优化大部分用户体验
    常用方法：
    1、限流：通过固定窗口、令牌桶或漏桶等方法限制
    2、排队防止超载

熔断：避免下游任务异常时候系统连锁故障（重点在切断调用）
1、监控服务健康状态：请求成功率、响应时间等
2、进入熔点状态
3、快速失败/降级处理
4、熔断灰度机制，熔断器半开测试

降级：提供简化版兜底（重点在简化替代） 



本项目限流规则：
    1、对单个接口整体限流
    2、对单个IP访问单个接口限流
1、查看题库列表接口限流熔断
资源:listQuestionBankVOByPage接口
    目的:控制对耗时较长的、经常访问的接口的请求频率，防止过多请求导致系统过载。限流规则:
    策略:整个接口每秒钟不超过10次请求
    阻塞操作:提示"系统压力过大，请耐心等待'熔断规则:
    熔断条件:如果接口异常率超过10%，或者慢调用(响应时长>3秒)的比例大于20%，触发60秒熔断。
    熔断操作:直接返回本地数据(缓存或空数据)
2、单IP查看题目列表限流熔断
资源:listQuestionVoByPage接口
    限流规则:
    策略:每个IP地址每分钟允许查看题目列表的次数不能超过60次。
    阻塞操作:提示"访问过于频繁，请稍后再试"熔断规则:
    熔断条件:如果接口异常率超过10%，或者慢调用(响应时长>3秒)的比例大于20%，触发60秒熔断。
    熔断操作:直接返回本地数据(缓存或空数据)



Sentinel核心概念
资源：需要限流/熔断的接口，通过设置
    资源可以自己注册，也可以使用官方对框架的适配依赖（https://sentinelguard.io/zh-cn/docs/open-source-framework-integrations.html）
规则：限流、熔断、系统访问、热点参数、授权
    控制台规则推送是采用HTTP API，仅仅在内存生效重启消失（管理和推送 https://github.com/alibaba/Sentinel/wiki/%E5%9C%A8%E7%94%9F%E4%BA%A7%E7%8E%AF%E5%A2%83%E4%B8%AD%E4%BD%BF%E7%94%A8-Sentinel）
生产环境规则管理和推送一般是push模式，即本地推送到配置中心，然后Sentinel客户端拉取

黑白名单：配置中心+布隆过滤器

Blloom Filter：
利用多个哈希将字符串映射到固定位数组上
有假阳性问题，且无法删除只能新增（没存储哈希之前的数据）

配置中心：
集中管理，避免单个实例重复配置
动态配置，实时更新
多环境多配置，避免混淆
版本控制，可以回滚提高容错
安全管理，加密数据库密码、API密钥等等

Nacos核心概念：
Namespace：在同一个集群里将不同环境（开发、测试、生产）隔离
Group：namespace再分组，一般用于区分多个模块
Data ID：使用场景:每个应用的配置都会有一个独特的DataID。例如，一个支付系统可能有一个配置文件叫 com.payment.pay-service.yaml,这就是它的Data ID。
Config Listener：动态配置，如调整缓存/切换服务端点等
